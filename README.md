# Employee Manager

Employee Manager is a Spring Boot application for registering and managing
employees. It provides:

- A server-rendered Thymeleaf web interface
- A REST API under `/api/employees`
- Create, read, update, and delete (CRUD) operations
- Case-insensitive employee-name search in the web interface
- Bean Validation for employee input
- MySQL persistence through Spring Data JPA and Hibernate

## Technology stack

- Java 25
- Spring Boot 4.1.1
- Spring MVC
- Spring Data JPA / Hibernate
- Thymeleaf
- MySQL
- Maven Wrapper
- Jakarta Bean Validation
- JUnit and Spring Boot Test

## Prerequisites

Install the following before running the application:

1. JDK 25
2. MySQL Server, or XAMPP with its MySQL service enabled

The default configuration connects to:

```text
Host:     localhost
Port:     3306
Database: employee_db
Username: root
Password: (empty)
```

The JDBC URL includes `createDatabaseIfNotExist=true`, so MySQL can create
`employee_db` on startup when the configured user has permission to do so.
Update [`application.properties`](employee-manager/src/main/resources/application.properties)
if your local database credentials differ.

## Running locally

From the repository root, change into the Maven module.

### Windows PowerShell

```powershell
cd employee-manager
.\mvnw.cmd spring-boot:run
```

### macOS/Linux

```bash
cd employee-manager
./mvnw spring-boot:run
```

Once the application starts, open <http://localhost:8080/>. The root route
redirects to `/employees`.

The application uses `spring.jpa.hibernate.ddl-auto=update`, which allows
Hibernate to create or update the `employees` table during development.
Review this setting before using the application in production.

## Web interface

| Route | Method | Description |
| --- | --- | --- |
| `/` | GET | Redirects to the employee list |
| `/employees` | GET | Displays the employee form and employee table |
| `/employees` | POST | Creates an employee from the form |
| `/employees?keyword=...` | GET | Searches employees by full name |
| `/employees/{id}/edit` | GET | Displays the edit form |
| `/employees/{id}/update` | POST | Updates an existing employee |
| `/employees/{id}/delete` | POST | Deletes an employee |

The web form supports the departments currently defined by the application:
Human Resources, Engineering, Finance, Sales, and Operations.

## REST API

The REST API is rooted at `/api/employees` and exchanges JSON.

| Route | Method | Success response | Other responses |
| --- | --- | --- | --- |
| `/api/employees` | GET | `200 OK` with an employee array | - |
| `/api/employees/{id}` | GET | `200 OK` with an employee | `404 Not Found` |
| `/api/employees` | POST | `201 Created` with the saved employee | `409 Conflict` for a duplicate email |
| `/api/employees/{id}` | PUT | `200 OK` with the updated employee | `404 Not Found`, `409 Conflict` |
| `/api/employees/{id}` | DELETE | `204 No Content` | `404 Not Found` |

### Employee JSON shape

```json
{
  "fullName": "Nimal Perera",
  "email": "nimal@example.com",
  "phone": "0771234567",
  "department": "Engineering",
  "age": 30,
  "salary": 85000.00
}
```

The `id` field is generated by the database when an employee is created.

### Example requests

Create an employee:

```powershell
curl.exe -X POST http://localhost:8080/api/employees `
  -H "Content-Type: application/json" `
  -d '{"fullName":"Nimal Perera","email":"nimal@example.com","phone":"0771234567","department":"Engineering","age":30,"salary":85000.00}'
```

List employees:

```powershell
curl.exe http://localhost:8080/api/employees
```

Update an employee:

```powershell
curl.exe -X PUT http://localhost:8080/api/employees/1 `
  -H "Content-Type: application/json" `
  -d '{"fullName":"Nimal Perera","email":"nimal@example.com","phone":"0771234567","department":"Engineering","age":31,"salary":90000.00}'
```

Delete an employee:

```powershell
curl.exe -X DELETE http://localhost:8080/api/employees/1
```

## Validation and business rules

The `Employee` model enforces the following rules for both the web form and
REST API:

- Full name is required and may contain up to 100 characters.
- Email is required, must have a valid email format, and must be unique.
- Phone is required and must contain exactly 10 digits.
- Department is required.
- Age is required and must be between 18 and 100.
- Salary is required and cannot be negative.

Duplicate email submissions are rejected by the web form with a validation
message and by the REST API with `409 Conflict`. During an update, the
employee's own existing email is excluded from the duplicate check.

## Configuration

Application settings are stored in
[`employee-manager/src/main/resources/application.properties`](employee-manager/src/main/resources/application.properties).
The main development settings are:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/employee_db
spring.datasource.username=root
spring.datasource.password=
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.thymeleaf.cache=false
```

For deployments outside local development, provide database credentials
through environment-specific configuration rather than committing secrets to
the repository. Consider replacing `ddl-auto=update` with an explicit
migration strategy and disabling SQL logging in production.

## Architecture

Requests are handled by two controllers:

- `EmployeeController` serves the Thymeleaf pages and form actions.
- `EmployeeRestController` serves JSON CRUD endpoints.

Both controllers use `EmployeeService`, which centralizes employee operations.
`EmployeeRepository` extends `JpaRepository` and adds queries for unique-email
checks and case-insensitive full-name search. The `Employee` class is both the
JPA entity stored in the `employees` table and the request/response model used
by the API.
